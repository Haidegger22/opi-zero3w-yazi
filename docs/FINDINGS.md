# Находки: превью картинок в yazi на этой плате

Записано по итогам живой работы на Orange Pi Zero 3W (Debian 13 trixie, arm64, MATE/X11, 1024×600).
Всё проверено на плате; там, где вывод основан на исходниках, указан файл и версия.

## 1. Симптом

yazi запускается, список файлов, иконки, превью текста с подсветкой и превью архивов работают —
а **панель превью для картинки пустая**. При этом `chafa`, запущенный вручную, картинку рисует.

## 2. Причина: порядок выбора драйвера

`yazi-adapter/src/drivers/drivers.rs` (v26.9.1), функция `Drivers::matches`:

```rust
pub fn matches(emu: &Emulator) -> D {
    let mut drivers: Self = emu.into();          // родные протоколы по бренду терминала
    if emu.sixel.get() && emu.mux.get().is_some_and(|mux| mux.sixel) { return D::Sixel; }
    ...
    if let Some(d) = drivers.first() { return *d; }   // терминал умеет показывать картинки сам

    let supported_compositor = Ueberzug::supported_compositor();
    match env::var("XDG_SESSION_TYPE").unwrap_or_default().as_str() {
        "x11" => return D::X11,
        ...
    }
    if env_exists("WAYLAND_DISPLAY") { ... }
    match env::var("DISPLAY").unwrap_or_default().as_str() {
        s if !s.is_empty() && !s.contains("/org.xquartz") => return D::X11,   // ← наш случай
        _ => {}
    }
    warn!("[Drivers] Falling back to chafa");
    D::Chafa
}
```

Что это значит практически:

- терминал **VTE** (MATE, XFCE4, GNOME — всё на VTE) не сообщает ни sixel, ни kitty-протокола,
  поэтому первый пункт не срабатывает;
- при непустом `DISPLAY` yazi возвращает **`D::X11`**, а драйвер X11 работает через **Überzug++**
  (`ueberzugpp`). Нет Überzug++ — драйвер молча ничего не рисует и **на chafa не переключается**;
- `D::Chafa` возвращается **только** если `DISPLAY` пуст и нет `WAYLAND_DISPLAY`.

Проверка фактов на терминале — `ya env`:

```
Emulator
    TERM: xterm-256color         (в xterm; VTE(8001) — в MATE)
    Emulator.probe: Emulator { brand: Unknown, version: ArcSwapAny("VTE(8001)"),
                               sixel: false, kgp: false, ... }
Adapter
    Drivers.matches: X11
    TERM.dimension : Dimension { cols: 80, rows: 22, width: 0, height: 0 }
```

## 3. Второе условие: chafa >= 1.16

Документация yazi (раздел Image Preview) прямо перечисляет способы и требования:

```
Fallback ASCII art (Unicode block) — ☑️ Chafa required (>= 1.16.0)
X11 / Wayland  Window system protocol — ☑️ Überzug++ required
```

В Debian 13 в репозитории **chafa 1.14.5** — младше требуемой, поэтому запасной путь не работает
даже после того, как `DISPLAY` убран. Сборка 1.18.3 из исходников заняла ~30 секунд и сняла вопрос.

## 4. Рабочее решение №1 (лучшее): xterm + sixel

`xterm` в Debian собран с sixel, и **сам сообщает о поддержке** — драйвер встроенный, ни Überzug++,
ни chafa не нужны, `DISPLAY` сохраняется:

```
Emulator.probe: ... sixel: true, version: XTerm(398)
Adapter: Drivers.matches: Sixel
TERM.dimension : Dimension { cols: 110, rows: 32, width: 664, height: 420 }   ← размеры в пикселях есть
```

Требуется режим VT340 (иначе sixel-запрос не поддержан): `xterm -ti vt340`. Обёртка `scripts/yazi-sixel`.

Отдельно полезно: у VTE `TERM.dimension` приходит как `width: 0, height: 0` — то есть терминал не
сообщает размер окна в пикселях (`ioctl` не реализован), из-за чего даже при рабочем драйвере картинка
не могла бы масштабироваться; xterm размеры отдаёт.

## 5. Рабочее решение №2 (запасное): chafa без DISPLAY

Собрать chafa ≥ 1.16 и запускать yazi с убранным `DISPLAY` — тогда драйвер chafa рисует картинку
блоками Unicode прямо в терминале MATE. Обёртка `scripts/yazi-img`.

Цена: без `DISPLAY` внутри yazi не работают открытие файлов внешними программами и системный
буфер обмена (`xclip`).

## 6. Что осталось непроверенным

**Überzug++** (`ueberzugpp`) — единственный путь для драйвера X11 (пиксельные картинки в терминале MATE
без обёрток). В Debian его нет, в релизах проекта готовых сборок arm64 нет — только сборка из исходников
(C++, нужны `libvips-dev` и X11-дев-пакеты). Классический `ueberzug` (Python, есть в Debian) yazi **не**
понимает: ему нужен именно `ueberzugpp`.

## 7. Как это проверялось

- Выбор драйвера — `ya env` внутри того терминала, где нужны превью (внешнее окружение не подходит:
  переменные `TERM`/`DISPLAY` разные).
- Живой результат — запуск yazi в терминале, выделение картинки, скриншот (`scrot`) и чтение кадра.
- Sixel самой утилитой: `sudo apt install libsixel-bin`, затем
  `xterm -ti vt340 -e "img2sixel -w 400 картинка.png; sleep 30"` — картинка должна появиться пиксельно.

### Автоматическая проверка TUI через псевдотерминал

Клавиши через X11 (`xdotool key`) на этой плате ненадёжны: фокус уходит на чужое окно, а `Enter`
на файле открывает редактор вместо входа в каталог. Надёжный способ — pty из Python:

```python
import pty, fcntl, struct, termios, os, time
pid, fd = pty.fork()
if pid == 0:
    os.execvpe("bash", ["bash", "-c", f'exec yazi "{D}" 2>/dev/null'], ENV)
fcntl.ioctl(fd, termios.TIOCSWINSZ, struct.pack("HHHH", 34, 120, 0, 0))  # без этого yazi не стартует!
time.sleep(3.5)
os.write(fd, b"j"); time.sleep(0.9)      # j/k — вниз/вверх, l — войти, h — выйти
```

- Размер pty обязательно выставлять через `TIOCSWINSZ`: у pty из `fork()` он 0×0, yazi с таким
  размером молча не рисуется, а клавиши эхо-отдаёт драйвер терминала (выглядит как «ничего не происходит»).
- Результат проверять **на диске** (`os.listdir`), а не по экрану: вывод полон escape-кодов.
- Готовый сценарий: `scripts/yazi-ops-test.py`.

## 8. Файловые операции (проверено на диске)

| Действие | Клавиши | Результат проверки |
|---|---|---|
| копировать в подкаталог | `j` `y` `k` `l` `p` | файл появился в подкаталоге, оригинал на месте |
| перенести | `j` `j` `x` `k` `k` `l` `p` | файл в подкаталоге, из исходного исчез |
| удалить в корзину | `d` + подтверждение `y` | файла в каталоге нет (ушёл в `~/.local/share/Trash`) |
| переименовать | `r` + имя + `Enter` | имя изменилось |
| скопировать путь | `c` `c` | в буфере обмена полный путь файла |
| скопировать имя | `c` `f` | только имя файла |
| скопировать путь каталога | `c` `d` | путь каталога |

Буфер обмена наполняется через `xclip` → **требует `DISPLAY`**: работает в `yazi-sixel` и в обычном
yazi, но не в `yazi-img`. Проверять содержимое буфера нужно **пока yazi жив**: после выхода владельца
выделения содержимое пропадает.

## 9. Корзина

- Вход: `g` `t` (плагин `trash`, виртуальная файловая система `trash://`).
- **Удалить навсегда**: выделить (`Space`, `Ctrl+a` — все) и нажать **`D`** + подтверждение.
  В исходниках это `fs.trash.remove` (`yazi-fs/src/trash/freedesktop/trash.rs`): стирается и файл,
  и его запись `*.trashinfo`. Проверено: файл исчез из `~/.local/share/Trash/files` вместе с записью в `info`.
- `d` (строчная) — «отправить **в** корзину», внутри корзины смысла не имеет.
- Корзина — стандартная freedesktop: `~/.local/share/Trash/{files,info}`, то же, что видит Caja.
  Снаружи yazi очистить можно так: `gio trash --empty`.
- **Восстановление** из корзины в штатном keymap на клавиши не вынесено (плагин умеет
  `trash-restore` / `trash-empty` через сообщения DDS — при необходимости привязывается вручную).

## 10. Русские подсказки

yazi не локализован, но подсказки клавиш — это поле `desc` из keymap, и его можно переопределить:
файл `~/.config/yazi/keymap.toml` с `prepend_keymap` в каждом слое имеет приоритет над штатным.
Генератор `scripts/yazi-ru-keymap.py` копирует пары «клавиша → действие» из штатного keymap
без изменений и подставляет русские описания (в 26.9.1 — 254 привязки в 8 слоях).

Два практических правила:

- подписи длиннее ~28 символов обрезаются в узких колонках всплывающего меню — держите их короткими;
- диалоги и уведомления самой программы (`Rename:`, `Trash 1 file?`) остаются английскими: они зашиты
  в бинарник и через настройки не меняются.
